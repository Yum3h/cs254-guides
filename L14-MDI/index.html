MDI: Multiple Document Interface

Many child windows inside one main window: JDesktopPane and JInternalFrame, the five ways to give an app several "documents" (internal frames, tabs, CardLayout, dialogs, separate frames), and CardLayout. Every slide of Lecture 14 – MDI (16 slides) in order, with a working desktop you can open, drag, minimise, maximise and close windows in, the same three documents shown all five ways, and a live CardLayout.

    Slides 1–7

    What MDI is

    In plain words
    Think of a desk inside a window. The JFrame is the room, the JDesktopPane is the desk that fills it, and each JInternalFrame is a sheet of paper on the desk. Sheets can overlap, be moved, minimised, maximised or closed, but none of them can leave the room. Three lines do it: make a JDesktopPane, add JInternalFrames to it (and make each visible!), and put the desktop in the frame.

    MDI 1

    MDI 2

    MDI – Multiple Document Interface

    • A user interface that allows multiple child windows inside a single main window.
    • Common in apps like Microsoft Word, Photoshop, Excel.

    Key Components 3

    PartWhat it isIn Java
    Main Frame (Parent Window)The main application window.Often called JFrame in Java.
    Child Frames (Internal Windows)Sub-windows inside the main frame.In Java, they are JInternalFrame.
    Desktop PaneA container to hold all internal frames.In Java, this is JDesktopPane.

    Features of MDI 4

    • Multiple documents can be open simultaneously.
    • Child windows can be minimized, maximized, or closed individually.
    • Main window controls all child windows.
    • Saves screen space compared to multiple top-level windows.

    Example 5

    JFrame mainFrame = new JFrame("MDI Example");
JDesktopPane desktop = new JDesktopPane(); // Holds child windows

JInternalFrame child1 = new JInternalFrame("Child 1",
true, true, true, true);
child1.setSize(200, 150);
child1.setVisible(true);

desktop.add(child1);
mainFrame.add(desktop);
mainFrame.setSize(500, 400);
mainFrame.setVisible(true);
    Guide noteThe four trues are, in order, resizable, closable, maximizable, iconifiable (iconify = minimise). An internal frame starts invisible and 0 × 0 pixels, so setSize (or pack()) and setVisible(true) are not optional: without them nothing appears. JDesktopPane has no layout manager, so also give each child a position with setLocation(x, y) (it starts at 0, 0). Add mainFrame.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE); so the program ends when the window closes.

    Added · a complete MDI program (File → New opens another child)
    
    
    MdiDemo.java
    import java.awt.*;
import javax.swing.*;
import javax.swing.event.*;

public class MdiDemo extends JFrame {
   private JDesktopPane desktop = new JDesktopPane();
   private int count = 0;

   public MdiDemo() {
      super("MDI Example");
      JMenuBar bar = new JMenuBar();
      JMenu file = new JMenu("File");
      JMenuItem newItem = new JMenuItem("New");
      newItem.addActionListener(e -> newDocument());
      file.add(newItem);
      bar.add(file);
      setJMenuBar(bar);                 // one menu bar controls every child (slide 6)

      desktop.setDragMode(JDesktopPane.OUTLINE_DRAG_MODE);
      add(desktop);                     // fills the CENTER of the frame
      setSize(500, 400);
      setDefaultCloseOperation(EXIT_ON_CLOSE);
      newDocument();
   }

   private void newDocument() {
      count++;
      JInternalFrame child = new JInternalFrame("Child " + count, true, true, true, true);
      child.add(new JScrollPane(new JTextArea()));
      child.setSize(200, 150);
      child.setLocation(24 * count, 24 * count);   // cascade the windows
      child.addInternalFrameListener(new InternalFrameAdapter() {
         public void internalFrameClosed(InternalFrameEvent e) {
            System.out.println(e.getInternalFrame().getTitle() + " closed");
         }
      });
      desktop.add(child);
      child.setVisible(true);
      try { child.setSelected(true); } catch (java.beans.PropertyVetoException ex) { }
   }

   public static void main(String[] args) {
      SwingUtilities.invokeLater(() -> new MdiDemo().setVisible(true));
   }
}
    
  
    

  
    
  
    

    


    
  
    
    
    Slides 8–13
    
    
    Five ways to implement MDI
    
  
    
  
    In plain words
    "Several documents in one program" can be built five ways, each a different trade-off between freedom and tidiness: overlapping internal windows (most like Word or Photoshop), tabs (tidy, one at a time), CardLayout (one panel at a time, switched by your code), dialogs (pop-up forms, possibly blocking the main window), or completely separate JFrames (most freedom, most clutter). The demo shows the same three documents all five ways.
    

  
    
    
    Ways to implement MDI: 8
    
    
      
      
    • Using JDesktopPane and JInternalFrame (Java Swing)
      • 
      
    • Using Tabbed Panes (JTabbedPane)
      • 
      
    • Using Custom Panels + CardLayout
      • 
      
    • Using Dialogs
      • 
      
    • Using Multiple Frames
      •

    JDesktopPane + JInternalFrame 9
    
    
      
      
    • Standard Java Swing approach.
      • 
      
    • Main Frame: JFrame
      • 
      
    • Child Windows: JInternalFrame
      • 
      
    • Container: JDesktopPane
      • 
    
    
    
    Pros: Multiple windows can overlap, minimize, maximize.
    Cons: Overlapping windows can confuse users.
    
  
    

  
    
    
    Tabbed Pane (JTabbedPane) 10
    
    
      
      
    • Each "document" is a tab instead of a window.
      • 
      
    • JTabbedPane holds multiple panels.
      • 
      
    • Easy to switch between documents via tabs.
      • 
    
    
    
    Pros: Simple, organized, no overlapping.
    Cons: Not a "true windowing" experience.
    
  
    

  
    
    
    CardLayout with Panels 11
    
    
      
      
    • Each document is a panel inside a container.
      • 
      
    • Only one panel visible at a time.
      • 
      
    • Switch documents programmatically using CardLayout.show().
      • 
    
    
    
    Pros: Lightweight, simple.
    Cons: Only one visible at a time, no minimize/maximize.
    
  
    

  
    
    
    Using Dialogs 12
    
    
      
      
    • Each document or child window is a dialog.
      • 
      
    • Can be modal (blocks parent) or non-modal (independent).
      • 
      
    • Good for temporary input forms, alerts, or small tools.
      • 
    
    
    
    Pros:
    
    
    • Simple to create and manage.
    • Can force user attention using modal dialogs.
    
    
    Cons:
    
    
    • Not ideal for complex MDI apps with many documents.
    • Doesn't provide a "stack of internal windows" look.
    
  
    

  
    
    
    Using Multiple Frames 13
    
    
      
      
    • Each document or child window is a separate JFrame.
      • 
      
    • Fully independent windows.
      • 
    
    
    
    Pros:
    
    
    • No restriction from parent window.
    • Each frame can have menus, toolbars, resizing, etc.
    
    
    Cons:
    
    
    • Can clutter the desktop if too many frames are open.
    • Harder to manage compared to JDesktopPane.
    
  
    

  
    Guide noteFor the final project's "at least two windows", the simplest choices are a second JFrame opened from a button (multiple frames) or a JDialog (Lecture 9). A modal dialog is made with new JDialog(parentFrame, "Title", true); the true means modal. When a second JFrame closes, use setDefaultCloseOperation(JFrame.DISPOSE_ON_CLOSE) on it, not EXIT_ON_CLOSE, or closing it ends the whole program.
    

  
    
  
    

    


    
  
    
    
    Slides 14–15
    
    
    JDesktopPane and JInternalFrame methods
    
  
    
  
    In plain words
    The desktop keeps track of its windows: getAllFrames() lists them and getSelectedFrame() tells you which one is active (handy for a "Save" menu item: save whichever document is in front). Each internal frame can be brought to the front or sent to the back, and you can listen to it: an InternalFrameListener hears it open, close, activate or minimise. The desktop demo in the first section uses all of these.
    

  
    
    
    JDesktopPane 14
    
    
    Helps Java Developers to make desktop-like applications, It allows the developers to manage and organize child frames within a parent frame.
    
    
    
      
    
        
    MemberWhat it does
    
        
          
    JDesktopPane()Constructor.
    
          
    add(JInternalFrame frame)Method for Adds a JInternalFrame(Child) to the JDesktopPane(Parent).
    
          
    remove(JInternalFrame frame)Method for Removes a JInternalFrame from the JDesktopPane
    
          
    getAllFrames()Method for Returns an array of all the internal frames within the JDesktopPane
    
          
    getSelectedFrame()Method for Returning the currently selected internal frame.
    
          
    DEFAULT_DRAG_MODEIt is a constant, that represents the default drag mode for internal frames.
    
          
    LIVE_DRAG_MODEThis constant indicates that when an internal frame is dragged within the JDesktopPane, the entire contents of the item should be visible during the drag operation.
    
          
    OUTLINE_DRAG_MODEThis constant indicates that, during the drag operation, only an outline or a frame-like representation of the item being dragged should appear inside the JDesktopPane.
    
          
    IS_CLOSED_PROPERTYIt is a Constant,that is used for check the internal frame is close or not.
    
            
      
    
    
    
  
    

  
    
    
    JInternalFrame 15
    
    
    A lightweight, child window that resides within a JDesktopPane in a Swing application. It behaves like a regular window (can be opened, closed, minimized, maximized, and moved) but is contained inside a main application frame, allowing multiple internal windows (MDI – Multiple Document Interface) within a single top-level JFrame
    
    
    
      
    
        
    MemberWhat it does
    
        
          
    JInternalFrame()Creates a non-resizable, non-closable, non-maximizable, non-iconifiable JInternalFrame with no title
    
          
    JInternalFrame(String title)
    
          
    JInternalFrame(String title, boolean resizable, boolean closable, boolean maximizable, boolean iconifiable)Creates a JInternalFrame with the specified title, resizability, closability, maximizability, and iconifiability.
    
          
    addImpl(Component comp, Object constraints, int index)Adds the specified child Component.
    
          
    addInternalFrameListener(InternalFrameListener l)Adds the specified listener to receive internal frame events from this internal frame.
    
          
    addPropertyChangeListener(PropertyChangeListener listener)Registers the specified listener to receive notifications whenever a bound property of the internal frame changes, including changes caused by user interaction or programmatic updates
    
          
    isSelected()Returns whether the JInternalFrame is the currently "selected" or active frame.
    
          
    toFront()Brings this internal frame to the front.
    
          
    toBack()Sends this internal frame to the back.
    
          
    show()If the internal frame is not visible, brings the internal frame to the front, makes it visible, and attempts to select it.
    
            
      
    
    
    
    
    For most internal frame events (open, close, activate, iconify): InternalFrameListener is simpler and clearer.
    
    
    For programmatic monitoring of specific properties or combined tracking: PropertyChangeListener is better.
    
  
    

  
    Guide noteDrag mode is set with desktop.setDragMode(JDesktopPane.OUTLINE_DRAG_MODE); live dragging is what you get if you don't call it. IS_CLOSED_PROPERTY is defined in JInternalFrame (the property name "closed"), for use with a PropertyChangeListener. addImpl is protected: you never call it, you call add(component), which uses it. For the frame itself, setVisible(true) is the usual call rather than show().
    

  
    
    
    Added · listening to internal frames, both ways
    
    
    child.addInternalFrameListener(new InternalFrameAdapter() {   // override only what you need
   public void internalFrameActivated(InternalFrameEvent e)  { status.setText(child.getTitle() + " is active"); }
   public void internalFrameIconified(InternalFrameEvent e)  { System.out.println("minimised"); }
   public void internalFrameClosing(InternalFrameEvent e)    { /* ask "Save changes?" here */ }
});

child.addPropertyChangeListener(JInternalFrame.IS_CLOSED_PROPERTY, evt -> {
   if (Boolean.TRUE.equals(evt.getNewValue())) System.out.println(child.getTitle() + " was closed");
});
    
    
    The seven InternalFrameListener methods: internalFrameOpened, Closing, Closed, Iconified, Deiconified, Activated, Deactivated. Like Lecture 5's adapters, InternalFrameAdapter lets you override just the ones you need.
    
  
    

  
    
  
    

    


    
  
    
    
    Slide 16
    
    
    CardLayout
    
  
    
  
    In plain words
    CardLayout stacks panels like a deck of cards and shows only the top one. Give each panel a name when you add it, then flip with next/previous (which wrap around), jump to first/last, or go straight to one with show(container, "name"). It's how "wizards" (Next → Next → Finish) and login-then-main-screen apps are usually built. Note that you call the methods on the layout and pass it the container.
    

  
    
    
    CardLayout 16
    
    
    manages the components in such a way that only one component is visible at a time. It treats each component as a card in the container. Only one card is visible at a time. The first component added to a CardLayout object is the visible component when the container is first displayed.
    
    
      
      
    • CardLayout()
      • 
      
    • first(Container parent) Shows the first component in the container.
      • 
      
    • last(Container parent) Shows the last component.
      • 
      
    • next(Container parent) Shows the next component. Wraps around to first after the last.
      • 
      
    • previous(Container parent) Shows the previous component. Wraps around to last before first.
      • 
      
    • show(Container parent, String name) Shows the component associated with the specified name.
      •

    CardLayout cardLayout = new CardLayout();
JPanel cards = new JPanel(cardLayout);          // the container that holds the cards

cards.add(welcomePanel, "welcome");             // the first card added is shown first
cards.add(detailsPanel, "details");
cards.add(confirmPanel, "confirm");
cards.add(donePanel,    "done");

nextButton.addActionListener(e -> cardLayout.next(cards));
backButton.addActionListener(e -> cardLayout.previous(cards));
editButton.addActionListener(e -> cardLayout.show(cards, "details"));

frame.add(cards, BorderLayout.CENTER);

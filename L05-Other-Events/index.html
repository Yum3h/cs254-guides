    Window events and adapters

    In plain words
    A WindowListener hears everything that happens to a window: opened, minimised, restored, focused, unfocused, closing, closed. It has seven methods, and an interface forces you to write all seven. WindowAdapter is a ready-made class with all seven left empty, so you extend it and override only the ones you care about. Most common use: windowClosing to ask "Are you sure?" before the program exits.

    Window Event in Java 3

    WindowListener:

    The interface defines methods to handle various window-related events, such as window opening, closing, activation, deactivation, and more.

    1. Windows Events 4

    Windows events in Java are triggered when a user interacts with a window, such as opening, closing, minimizing, or resizing a window. These events are handled using the WindowListener interface.

    1. windowOpened(WindowEvent e): Invoked when the window is first opened or displayed.
    2. windowClosing(WindowEvent e): Triggered when the user attempts to close the window.
    3. windowClosed(WindowEvent e): Sent after the window has been closed.
    4. windowIconified(WindowEvent e): Occurs when the window is minimized.
    5. windowDeiconified(WindowEvent e): Triggered when the window is restored from a minimized state.
    6. windowActivated(WindowEvent e): Fired when the window receives focus and becomes active.
    7. windowDeactivated(WindowEvent e): Sent when the window loses focus and becomes inactive.

    WindowAdapter 5

    WindowAdapter:
    It is an abstract class that implements the WindowListener interface. It provides default empty implementations for all the methods of the WindowListener interface. We can extend WindowAdapter and override only the methods you need, making it convenient for handling specific window events without implementing all the methods.

    Registering Window Listeners
    To handle window events, you need to register a WindowListener or a subclass of WindowAdapter to a window component (usually a JFrame, JDialog, or JWindow). You can do this using the addWindowListener(WindowListener l) method.

    frame.addWindowListener(new WindowAdapter() {
    // Override window event methods as needed
});

    Handling Window Events in Java 6

    To handle window events in Java, you need to implement the WindowListener or WindowAdapter interface. The WindowAdapter class provides default empty implementations for all methods of the WindowListener interface, allowing us to override only the methods relevant to your application.

    Guide noteStrictly, you implement WindowListener (an interface) but extend WindowAdapter (a class).

    Difference Between Java Listener and Java Adapter in Event Handling 7

    In Java's event handling mechanism, both listeners and adapters are used to respond to user interactions such as button clicks, mouse movements, and keyboard events. However, they have different roles and usage.

    FeatureListenerAdapter
    DefinitionAn interface with multiple abstract methods that must be implemented by the class using the listener.A convenience class that provides default (empty) implementations of listener interface methods.
    ImplementationA class implementing a listener interface must override all of its methods, even if only one method is needed.A class can extend the adapter and override only the required methods, avoiding unnecessary boilerplate code.
    UsageUsed when all or most methods of an event listener interface need to be implemented.Used when only a few methods of an event listener interface need to be implemented.
    FlexibilityLess flexible as it requires implementing all methods.More flexible because it provides default implementations for unused methods.
    Example InterfacesMouseListener, KeyListener, FocusListenerMouseAdapter, KeyAdapter, FocusAdapter
    Inheritance RequirementA class implementing a listener interface can extend any other class (as Java supports multiple interface implementation).Since Java does not support multiple inheritance, a class extending an adapter class cannot extend another class.

    Exercise: all window events 9

    Write a Java Swing program that demonstrates the use of WindowListener to handle various window events such as opening, closing, minimizing, and restoring a window.

    Instructions:

    1. Create a JFrame with the title "All Window Events Example".
    2. Set the frame size to 400x300 pixels.
    3. Use WindowListener to detect and respond to the following events:
      1. windowOpened → Print "Window Opened" when the window appears.
      2. windowClosing → Ask the user for confirmation before closing the window.
      3. windowClosed → Print "Window Closed" after the window is closed.
      4. windowIconified → Print "Window Minimized" when minimized.
      5. windowDeiconified → Print "Window Restored" when restored.
      6. windowActivated → Print "Window Activated" when the window gains focus.
      7. windowDeactivated → Print "Window Deactivated" when the window loses focus.
    Added · Show a solution
    AllWindowEvents.java
    import javax.swing.*;
import java.awt.event.*;

public class AllWindowEvents extends JFrame implements WindowListener {

    public AllWindowEvents() {
        super("All Window Events Example");
        setSize(400, 300);
        // we decide ourselves in windowClosing, so don't close automatically
        setDefaultCloseOperation(JFrame.DO_NOTHING_ON_CLOSE);
        addWindowListener(this);
        setVisible(true);
    }

    public void windowOpened(WindowEvent e)      { System.out.println("Window Opened"); }
    public void windowClosed(WindowEvent e)      { System.out.println("Window Closed"); System.exit(0); }
    public void windowIconified(WindowEvent e)   { System.out.println("Window Minimized"); }
    public void windowDeiconified(WindowEvent e) { System.out.println("Window Restored"); }
    public void windowActivated(WindowEvent e)   { System.out.println("Window Activated"); }
    public void windowDeactivated(WindowEvent e) { System.out.println("Window Deactivated"); }

    public void windowClosing(WindowEvent e) {
        int choice = JOptionPane.showConfirmDialog(this,
                "Are you sure you want to close?", "Confirm", JOptionPane.YES_NO_OPTION);
        if (choice == JOptionPane.YES_OPTION) {
            dispose();          // closes the window, which then fires windowClosed
        }
    }

    public static void main(String[] args) {
        new AllWindowEvents();
    }
}

    All seven methods are written because the class implements WindowListener. dispose() is used instead of EXIT_ON_CLOSE so that windowClosed actually runs; with EXIT_ON_CLOSE the program ends before windowClosed is called.

    Difference Between windowClosing and windowClosed 10

    Both windowClosing() and windowClosed() belong to the WindowListener interface, but they handle different stages of closing a window.

    MethodTriggered When…Can Prevent Window from Closing?Common Use Cases
    windowClosing(WindowEvent e)The user clicks the close (X) button or calls dispose().Yes – You can show a confirmation dialog or cancel the close action.Asking for user confirmation before closing.
    windowClosed(WindowEvent e)The window has completely closed and resources are released.No – The window is already closed when this event fires.Logging, saving state, or cleanup operations.
    Guide noteClicking X fires windowClosing. Calling dispose() from code fires only windowClosed.

    Key events

    In plain words
    Each key stroke can fire up to three methods: keyPressed (key goes down), keyTyped (a character was produced) and keyReleased (key comes up). Shift, Ctrl and arrow keys fire pressed/released but not typed, because they don't produce a character. Use getKeyCode() + KeyEvent.VK_… constants in pressed/released, and getKeyChar() in typed. Try it in the box below the slides.

    KeyListener interface 13

    public interface KeyListener {
    public void keyPressed(KeyEvent event);
    public void keyReleased(KeyEvent event);
    public void keyTyped(KeyEvent event);
}
    • Many AWT/Swing components have this method:
      • public void addKeyListener(KeyListener kl)
    • The abstract class KeyAdapter implements all KeyListener methods with empty bodies.

    The difference between keyTyped() and keyPressed() 16–17

    • keyPressed(KeyEvent e):
      • Fires when a key is pressed down on the keyboard.
      • It captures the physical action of pressing a key, regardless of whether the key is a character or a non-character key (like shift, ctrl, or function keys).
      • You can get the key code using e.getKeyCode().
      • Example: This method is triggered when you press a key, such as the "A" key or the "Shift" key.
      public void keyPressed(KeyEvent e) {
    System.out.println("Key Pressed: " + e.getKeyChar()); }
    • keyTyped(KeyEvent e):
      • Fires when a key is typed, which is generally when the key has been pressed and released.
      • This method only deals with characters (letters, digits, symbols) and ignores non-character keys (e.g., Shift, Ctrl).
      • You can get the character typed using e.getKeyChar().
      • Example: This method is triggered when you type a character key, like "A", "1", or "!".
      public void keyTyped(KeyEvent e) { System.out.println("Key Typed: " +
    e.getKeyChar()); }

    Key Differences:

    • Timing: keyPressed() is triggered when the key is pressed, whereas keyTyped() is triggered when the key is typed (press + release).
    • Event Type: keyPressed() works for all keys (character and non-character), while keyTyped() only works for character keys.
    • Usage: keyPressed() is useful when you need to detect any key press, while keyTyped() is specifically used when handling character input.
    Guide noteIn practice Java fires keyTyped right after keyPressed, before the key is released. The order is pressed → typed → released.

    Key event example 2 19–20

    import java.awt.*;
import java.awt.event.*;
import javax.swing.*;

public class KeyDemo extends JFrame implements KeyListener {
   private String line1 = "", line2 = "", line3 = "";
   private JTextArea textArea;

   // set up GUI
   public KeyDemo() {
      super( "Demonstrating Keystroke Events" );

      // set up JTextArea
      textArea = new JTextArea( 10, 15 );
      textArea.setText( "Press any key on the keyboard..." );
      textArea.setEnabled( false );
      textArea.setDisabledTextColor( Color.BLACK );
      getContentPane().add( textArea );

      addKeyListener( this );   // allow frame to process Key events

      setSize( 350, 100 );
      setVisible( true );
   } // end KeyDemo constructor

   // handle press of any action key
   public void keyPressed( KeyEvent event )
   {
      line1 = "Key pressed: " + event.getKeyText( event.getKeyCode() );
      setLines2and3( event );
   }

   // handle release of any key
   public void keyReleased( KeyEvent event )
   {
      line1 = "Key released: " + event.getKeyText( event.getKeyCode() );
      setLines2and3( event );
   }

   // handle press of any non-action key
   public void keyTyped( KeyEvent event )
   {
      line1 = "Key typed: " + event.getKeyChar();
      setLines2and3( event );
   }

   // set second and third lines of output
   private void setLines2and3( KeyEvent event )
   {
      line2 = "This key is " + ( event.isActionKey() ? "" : "not " ) + "an action key";

      String temp = InputEvent.getModifiersExText( event.getModifiersEx() );

      line3 = "Modifier keys pressed: " + ( temp.equals( "" ) ? "none" : temp );

      textArea.setText( line1 + "\n" + line2 + "\n" + line3 + "\n" );
   }

   public static void main( String args[] )
   {
      KeyDemo application = new KeyDemo();
      application.setDefaultCloseOperation( JFrame.EXIT_ON_CLOSE );
   }

} // end class KeyDemo

    Focus and component events

    In plain words
    Focus is "where the keyboard is pointing". When you click into a text field it gains focus; when you click elsewhere it loses it. Use it to highlight the active field or to validate a field when the user leaves it. Component events fire when a component is resized, moved, shown or hidden.

    Focus events 22

    public interface FocusListener {
    public void focusGained(FocusEvent event);
    public void focusLost(FocusEvent event);
}
    • focus: The current target of keyboard input.
      • A focus event occurs when the keyboard cursor enters or exits a component, signifying the start/end of typing on that control.
    • Many AWT/Swing components have this method:
      • public void addFocusListener(FocusListener kl)
    • The abstract class FocusAdapter implements all FocusListener methods with empty bodies.

    Focus Event example 23

    import java.awt.*;
import java.awt.event.*;
class TextFieldFocusEvent extends Frame implements FocusListener
{
    TextField t1,t2;

    public TextFieldFocusEvent()
    {
        createAndShowGUI();
    }

    private void createAndShowGUI()
    {
        setTitle("FocusListener for TextField");
        setLayout(new FlowLayout());

        // Create 2 textfields
        t1=new TextField(20);
        t2=new TextField(20);

        // Add them
        add(t1);
        add(t2);

        // Add FocusListeners
        t1.addFocusListener(this);
        t2.addFocusListener(this);

        setSize(400,400);
        setVisible(true);
    }

    public void focusGained(FocusEvent fe)
    {
        // Get what textfield got focus
        TextField t=(TextField)fe.getSource();
        t.setBackground(Color.LIGHT_GRAY);
    }

    public void focusLost(FocusEvent fe)
    {
        // Get what textfield lost focus
        TextField t=(TextField)fe.getSource();
        t.setBackground(Color.WHITE);
    }

    public static void main(String args[])
    {
        new TextFieldFocusEvent();
    }
}

    Slides 25–28

    JList selection events

    In plain words
    A JList doesn't fire ActionEvents. It fires a ListSelectionEvent whenever the selection changes, and you handle it in valueChanged. One click can fire several events in a row while the selection is "adjusting", so wrap your code in if (!e.getValueIsAdjusting()) to run it once, on the final value.

    JList select event 25

    public interface ListSelectionListener {
    public void valueChanged(ListSelectionEvent event);
}
    • These events occur when a user changes the element(s) selected within a JList.
    • The JList component has this method:
      • public void addListSelectionListener(ListSelectionListener lsl)

    ListSelectionListener Interface 26

    • public void valueChanged(ListSelectionEvent evt)
    • This method is automatically called by the runtime system every time the selection is changed. It is not executed if the selection is unchanged, for example if the user clicks in an item that is already selected
    • The body of this method has to contain the code that should be executed in response to the selection.

    ListSelectionEvent

    • getFirstIndex() returns the position of the first (top-most) entry, the selection mode of which might have changed (from selected to non-selected or vice versa). 'Might' refers to the fact that the section state might be the same as before. For example if entries 5 to 8 were selected and the user now selects 5 to 10 then the first selected index remains unchanged. Which entries are selected can be found by using method getSelectedIndices of class JList.
    • getLastIndex() returns the position of the last (bottom-most) entry, the selection mode of which might have changed. See also getFirstIndex().
    • getIsAdjusting – changing the selection in a list triggers a series of actions, each of which generates a list selection event. For example previously selected entries become unselected before new ones become selected. Usually, one would prefer this series of events to be completed before the application reacts to the change. For such a rapid series of events all but the last one return true as a result of getIsAdjusting. Only the last one returns false as a result of getIsAdjusting. This can be used to wait for the end of the series of adjustments before taking further action.
    • At the moment, ListSelectionEvent supports only the selection modes SINGLE_SELECTION and SINGLE_INTERVAL_SELECTION.
    Guide noteThe real method name is getValueIsAdjusting(), as the code on slide 28 uses.

    Document, item and change events

    In plain words
    • DocumentListener: runs on every change to a text field's text (typing, deleting, pasting), not just on Enter. Good for live character counters or live validation.
    • ItemListener: runs when a check box or combo-box item becomes selected or deselected. getStateChange() tells you which.
    • ChangeListener: runs when a slider, spinner or tabbed pane changes value.

    Document events 29

    public interface DocumentListener {
    public void changedUpdate(DocumentEvent event);
    public void insertUpdate(DocumentEvent event);
    public void removeUpdate(DocumentEvent event);
}
    • These events occur when the contents of a text component (e.g. JTextField or JTextArea) change.
    • Such components have this method:
      • public Document getDocument()
    • And a Document object has this method:
      • public void addDocumentListener(DocumentListener cl)

    Good to know for this lab

    • The coordinates only change over the empty grey area. Buttons, the text field and the text area have their own mouse listeners, so Java sends the mouse events to them instead of the panel. The handout's numbers (X: 5, Y: 2 and so on) come from the panel's empty space too.
    • Why the empty methods? MouseListener (5 methods), MouseMotionListener (2) and KeyListener (3) are interfaces, and a class that implements an interface must write every one of its methods, even the ones it doesn't use. Leave out an empty one and NetBeans shows an error.
    • mouseClicked needs a clean click. It runs only when the mouse button is pressed and released in the same spot. If the mouse moves while you click, there is no click event and no message; just click again.
    • Local variables inside anonymous classes must never be given a new value (they are "effectively final"). That is why the name is read inside each listener instead of being kept in a variable that changes.

    WindowAdapter on the framewindowClosing asks "Are you sure you want to exit?". Swing runs your windowClosing first and then applies the default close operation, so switching it to EXIT_ON_CLOSE (Yes) or DO_NOTHING_ON_CLOSE (No) inside the listener decides what happens next. The other methods print to the console.

    • "Window closed!" never prints when the user picks Yes: with EXIT_ON_CLOSE the program ends before windowClosed is called (same point as slide 10).
    • No empty-field check: Sign Up accepts an empty username. Lab 4's validation adds that.

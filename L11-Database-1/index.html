    Slides 1–3

    What JDBC is

    In plain words
    Your Java program can't speak "MySQL" or "Oracle" directly. JDBC is the translator in the middle: you write SQL as ordinary Strings, JDBC carries it to the database and brings the answer back. Think of a phone call:
    • DriverManager is the operator who finds the right phone line (the driver) for the number you dial (the URL).
    • The Connection is the open call.
    • A Statement is a sentence you say (one SQL command).
    • The ResultSet is the answer, which you read one row at a time.

    • JDBC receives queries from a Java Application program and communicate with Database
    • All the communications are in the form of SQL commands
    • JDBC is reponsible for
      • Open a Connection

      • Retrive query results

    JDBC - Conceptual Components 3

    • Driver Manager: Loads database drivers and manages connections between the application and the driver
    • Driver: Translates API calls into operations for specific database
    • Connection: Session between application and data source
    • Statement: SQL statement to perform query or update
    • Metadata: Information about returned data, database, & driver
    • Result Set: Logical set of columns and rows of data returned by executing a statement

    Slide 4

    The eight basic steps

    In plain words
    Every JDBC program follows the same recipe. Memorise it as: import → load driver → URL → connect → statement → execute → read rows → close. The step-through below runs a complete program against the little database inside this page, one step at a time.

    JDBC - Basic Steps 4

    1. Import the necessary classes
    2. Load the JDBC driver
    3. Identify the data source (Define the Connection URL)
    4. Establish the Connection
    5. Create a Statement Object
    6. Execute query string using Statement Object
    7. Retrieve data from the returned ResultSet Object
    8. Close ResultSet & Statement & Connection Object in order

    JdbcSteps.java
    // 1. Import the necessary classes
import java.sql.*;

public class JdbcSteps {
   public static void main(String[] args) {
      Connection conn = null;
      Statement stmt = null;
      ResultSet rs = null;
      try {
         // 2. Load the JDBC driver
         Class.forName("com.mysql.cj.jdbc.Driver");
         // 3. Identify the data source (define the connection URL)
         String url = "jdbc:mysql://localhost:3306/university";
         // 4. Establish the connection
         conn = DriverManager.getConnection(url, "root", "password");
         // 5. Create a Statement object
         stmt = conn.createStatement();
         // 6. Execute the query string using the Statement object
         rs = stmt.executeQuery("SELECT id, name, grade FROM students");
         // 7. Retrieve data from the returned ResultSet object
         while (rs.next()) {
            System.out.println(rs.getInt("id") + "  " + rs.getString("name") + "  " + rs.getInt("grade"));
         }
      } catch (ClassNotFoundException e) {
         System.out.println("Driver not found: " + e.getMessage());
      } catch (SQLException e) {
         System.out.println("Database error: " + e.getMessage());
      } finally {
         // 8. Close ResultSet, Statement and Connection, in that order
         try {
            if (rs != null) rs.close();
            if (stmt != null) stmt.close();
            if (conn != null) conn.close();
         } catch (SQLException e) {
            e.printStackTrace();
         }
      }
   }
}

    Slides 5–7

    DriverManager and the driver

    In plain words
    Each database brand ships its own driver: a JAR file with a class that knows how to talk to that database. Class.forName("…Driver") loads that class by name; loading it makes the driver register itself with DriverManager. Later, when you ask DriverManager for a connection, it asks each registered driver "can you handle this URL?" and the first one that says yes opens the connection. You never write new DriverManager(): everything on it is static.

    JDBC - Driver Manager 5

    • DriverManager provides a common access layer on top of different database drivers
      • Responsible for managing the JDBC drivers available to an application
      • Hands out connections to the client code
    • Maintains reference to each driver
      • Checks with each driver to determine if it can handle the specified URL
      • The first suitable driver located is used to create a connection
    • DriverManager class can not be instantiated
      • All methods of DriverManager are static
      • Constructor is private

    Load and Register Driver 6

    Class.forName("Driver ClassName");

    e.g.,

    1 Class.forName("sun.jdbc.odbc.JdbcOdbcDriver")
2 Class.forName("com.mysql.jdbc.Driver");

    Note: Calling the Class.forName automatically creates an instance of a driver and registers it with the DriverManager, so you don't need to create an instance of the class

    Opening a connection

    In plain words
    DriverManager.getConnection(url, user, password) dials the database. The URL always starts with jdbc:, then names the driver type, then says where the database is. If the driver class can't be found you get a ClassNotFoundException; if anything goes wrong talking to the database (server off, wrong password, unknown database) you get an SQLException. That's why the examples have two catch blocks.

    Establish Connection 8

    Connection conn = DriverManager.getConnection("URL");
Connection conn = DriverManager.getConnection(url, username, password);

    • The DriverManager class,manages all of the details of establishing the connection
    • The connection returned by the method DriverManager.getConnection is an open connection you can use to create JDBC statements that pass your SQL statements to the DBMS.

    Closing a connection
    
  
    
  
    In plain words
    A database can only keep a limited number of connections open at once. Every connection you forget to close is "leaked": it stays busy until the program ends. Leak enough of them and the next getConnection has nothing left to give you, so the program hangs. Code inside finally runs whatever happens in the try (normal end, caught exception, uncaught exception, even a return), so that's where close() belongs.
    

  
    
    
    Connection - Closing 11
    
    
      
      
    • Each machine has a limited number of connections (separate thread)
        
      • If connections are not closed the system will run out of resources and freeze
      • Syntax: public void close() throws SQLException
      • 
    
    
    
    
      
    
        
    • Naïve Way:
    
        
    try {
   Connection conn =
      DriverManager.getConnection(url);
   // Jdbc Code
   …
} catch (SQLException sqle)
{
   sqle.printStackTrace();
}
conn.close();
    
        
    • SQL exception in the Jdbc code will prevent execution to reach conn.close()
    
      
    
      
    
        
    • Correct way (Use the finally clause)
    
        
    try{
   Connection conn =
      Driver.Manager.getConnection(url);
   // JDBC Code
} catch (SQLException sqle)
{
   sqle.printStackTrace();
} finally {
   try {
      conn.close();
   } catch (Exception e) {
      e.printStackTrace();
   }
}

Declare it first: Connection conn = null; and close with if (conn != null) conn.close();. Also, strictly, the naïve snippet's catch swallows an SQLException and carries on to conn.close(). It leaks when the exception is one the catch doesn't handle (e.g. a NullPointerException) or when the catch returns or re-throws. Try each case below.

    Statement
    
  
    
  
    In plain words
    Once connected, ask the connection for a Statement: connection.createStatement(). One Statement can send as many SQL commands as you like, one after another. When you're done, close it (in finally, like the connection) so its resources are freed straight away instead of "some time later" when the garbage collector notices nobody uses it.

    Executing queries
    
  
    
  
    In plain words
    Two methods, one rule: does the SQL give you rows back?
    • Yes (SELECT) → executeQuery(sql), which returns a ResultSet.
    • No (INSERT, UPDATE, DELETE, CREATE, DROP, ALTER) → executeUpdate(sql), which returns an int: how many rows changed (always 0 for CREATE/DROP/ALTER).
    The SQL itself is just a Java String, so long commands are glued together with +. Watch the spaces and quotes where the pieces join.
    

  
    
    
    Statement Methods - Executing Queries 14
    
    
      
      
    • Two primary methods in statement interface used for executing Queries
        
      • executeQuery Used to retrieve data from a database
      • executeUpdate: Used for inserting, updating & deleting data
      • 
      
    • executeQuery used to retrieve data from database
        
      • Primarily uses Select commands
      • 
      
    • executeUpdate used for creating, updating & deleting data
        
      • SQL should contain Update, Insert or Delete commands
      • 
      
    • Uset setQueryTimeout to specify a maximum delay to wait for results
      • 
    
    
    
    Added · setQueryTimeout

    ResultSet
    
  
    
  
    In plain words
    A ResultSet is the table of rows your SELECT returned, with a cursor: an arrow pointing at one row. It starts before the first row, so you must call rs.next() before reading anything. Each next() moves down one row and says true if there was a row there, false when you've gone past the end. That's why the standard loop is while (rs.next()) { … }. To read a column of the current row, call the getXxx that matches its type, by name or by number, and remember the first column is 1, not 0.
    

  
    
    
    ResultSet - Definition 18
    
    
      
      
    • ResultSet contains the results of the database query that are returned
      • 
      
    • Allows the program to scroll through each row and read all columns of data
      • 
      
    • ResultSet provides various access methods that take a column index or column name and returns the data
        
      • All methods may not be applicable to all resultsets depending on the method of creation of the statement.
      • 
      
    • When the executeQuery method returns the ResultSet the cursor is placed before the first row of the data
        
      • Cursor refers to the set of rows returned by a query and is positioned on the row that is being accessed
      • To move the cursor to the first row of data next() method is invoked on the resultset
      • If the next row has a data the next() results true else it returns false and the cursor moves beyond the end of the data
      • 
      
    • First column has index 1, not 0
      • 
      
    • Depending on the data numerous functions exist
        
      • getShort(), getInt(), getLong()
      • getFloat(), getDouble()
      • getClob(), getBlob(),
      • getDate(), getTime(), getArray(), getString()
      •

      for (int i = 1; i <= nCols; i++)
         row[i - 1] = rs.getObject(i);            // JDBC columns start at 1, arrays at 0
      model.addRow(row);
   }
   return model;
}

// inside your JFrame, e.g. in a button's actionPerformed:
try (Connection conn = DriverManager.getConnection(url, user, password);
     Statement stmt = conn.createStatement();
     ResultSet rs = stmt.executeQuery("SELECT * FROM students")) {
   table.setModel(toTableModel(rs));
} catch (SQLException ex) {
   JOptionPane.showMessageDialog(this, ex.getMessage(), "Database error", JOptionPane.ERROR_MESSAGE);
}
